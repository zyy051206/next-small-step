# 下一小步

一个把目标变成小行动的本地优先工具。原生 HTML / CSS / JavaScript，核心功能无需联网；原生应用可联网检查公开的新版本。

**Windows EXE + 安卓 APK + 电脑/手机网页**，使用同一份界面和备份格式，离线可用。各端不自动同步，可以用 JSON 备份迁移。

写下一个目标，拆成今天能完成的小行动，再用一段专注时间开始。支持电脑和手机，无需注册，进度由你自己保存。

## 打开

在 [v2.3.0 发布页](https://github.com/zyy051206/next-small-step/releases/tag/v2.3.0) 选择：

| 平台 | 下载与运行 |
| --- | --- |
| Windows 10/11 x64 | [下载 2.3.0 EXE](https://github.com/zyy051206/next-small-step/releases/download/v2.3.0/next-small-step-2.3.0-windows-x64.exe)，关闭旧程序后运行安装，之后从开始菜单或桌面快捷方式打开 |
| Android 8.0 及以上 | [下载 2.3.0 APK](https://github.com/zyy051206/next-small-step/releases/download/v2.3.0/next-small-step-2.3.0.apk)，传到手机覆盖安装 |
| 电脑/手机浏览器 | 在线网页；或[下载网页 ZIP](https://github.com/zyy051206/next-small-step/releases/download/v2.3.0/next-small-step-browser-2.3.0.zip)，在电脑解压后打开 `index.html` |

EXE 未做 Windows 数字签名，系统可能显示未知发布者；发布页提供 SHA-256 校验值。iPhone 使用网页版。

下载仓库后，双击 `dist/index.html` 即可使用，无需安装依赖。

如已安装 Node.js，也可以在项目目录启动本地服务：

```sh
node serve.cjs
```

打开终端显示的地址（默认 `http://127.0.0.1:4177`）。数据按浏览器和访问地址隔离，文件方式与 localhost 不共享数据，请用导出/导入迁移。

首次使用时，创建目标并添加行动，点击某条行动后选择专注时长；行动做完后手动勾选完成。在“专注足迹”页可以导出和导入 JSON 备份。

## 2.3.0

- 今日番茄清单：当天与已逾期的待办集中在一处，可以直接选中开始专注。
- 每项待办可预估番茄数（0–12）。完整专注结束后自动为当前待办累计番茄，小步列表和今日清单都会显示进度。
- 每日番茄目标（1–24）与今日进度点；「专注足迹」新增累计番茄。
- 沉浸专注模式：全屏显示任务、倒计时和今日进度，按 Esc 退出后计时继续。
- 离线白噪音：雨声、微风和白噪音由浏览器本地合成，可调音量；不下载音频素材，只在沉浸模式中播放。
- 数据格式升级到 v3，兼容导入 v1/v2 备份。旧备份中的历史专注仍保留，待办番茄从升级后开始累计。

## 功能

- 工作台、日历计划、重要日子、专注足迹分为四页；支持直接链接、刷新和浏览器前进后退。切页保留计时和当前日历、统计选择。
- 多目标及行动列表，支持新增、编辑、删除、撤销完成；待办可设置日期和优先级。
- 学习、创作、求职三种可编辑行动模板；不会自动生成假进度。
- 日历与每日计划：按日期安排任务，查看未安排和已逾期事项，与目标列表和专注任务联动。
- 重要日期：倒数/已过天数、分类、置顶、每年重复，支持生日、考试、纪念日。
- 番茄专注：快捷或自定义 5–180 分钟，短/长休息、番茄轮次、暂停/继续、刷新恢复、提前完成。完成一段后手动开始下一段，休息不计入专注统计。
- 番茄待办：为待办预估番茄数，完整专注后自动累计；今日清单汇总当天与逾期事项，每日目标显示完成进度。
- 沉浸专注与白噪音：全屏专注界面，可播放本地合成的雨声、微风或白噪音。
- 累计统计、最近七天 / 全年十二个月视图，可切换历史年份。
- 每月专注时长、次数、活跃天数和全年合计；手机明细表可横向滑动。全部历史记录可导出。
- JSON 备份导入/导出，导入前校验和二次确认，异常存储保护。
- 外观设置：选择本地背景图片、调节浅色遮罩；应用内图标和 Logo 支持常用色板与自定义颜色，可恢复默认。
- 手机布局、键盘操作、减少动态效果支持。
- 安卓 APK 内置页面，离线运行；通过系统文件选择器导入和导出备份。
- Windows EXE 内置页面，离线运行；备份通过系统窗口保存，升级 EXE 保留本机进度。
- EXE / APK 提供“检查更新”：启动时自动检查，并在应用使用期间每隔六小时检查；发现新版显示不打断操作的提醒，也可关闭自动检查。

## 检查与下载更新

电脑版和安卓版可以在导航区点击“检查更新”（窄屏为循环箭头图标），查看版本说明和下载大小。从 v2.0.3 起，下载在应用内完成并显示进度，支持取消和重试；校验通过后才可以安装。Windows 点击“重启并更新”自动安装并重新打开；Android 点击“安装更新”直接进入系统安装确认，首次可能需要允许本应用安装更新。无需跳转浏览器或查找安装包。

v2.0.2 及以前的版本需要先按旧方式下载并安装一次 v2.0.3。Windows 从便携版改为当前用户安装版，之后请从开始菜单或新建的快捷方式打开；数据继续使用原目录。Android 沿用原包名和签名，覆盖安装即可，保留记录和外观。更新检查和下载仅在应用运行时进行；不发送目标、专注记录、图片或登录凭据。网页版本不显示原生安装包更新入口。

## 安卓安装与迁移

在 [Releases](https://github.com/zyy051206/next-small-step/releases) 下载 `next-small-step-2.3.0.apk`，传到安卓手机并打开安装。支持 Android 8.0 及以上，建议使用更新后的 Android System WebView。手机可能要求允许此次来源安装应用。新版沿用正式版签名，可覆盖安装 v1.1.0 / v2.0.0；升级前建议导出备份。

电脑已有进度：先在原网页点“导出备份”，把 JSON 文件传到手机，再在 App 中点“导入备份”。导入会在确认后替换目标设备的现有数据，不会自动合并。卸载 App 会清除其本地数据，请先备份。iPhone 可使用网页版本，不能安装 APK。

计时切到后台或锁屏后按实际时钟计算，回到 App 时恢复显示或补记结束；可在番茄钟设置开启通知；Android 使用系统定时提醒，需允许通知与准时提醒权限。强行停止应用、系统勿扰或厂商省电设置可能阻止提醒。

安卓源码、构建和签名说明见 [android/README.md](android/README.md)。GitHub Actions 会构建 APK 并用 Android 模拟器验证离线页面与数据持久化。CI 的 debug APK 仅供测试，正式交付包使用固定本地签名。

Windows 进度保存在 `%APPDATA%\NextSmallStep`，安装版升级不改变数据目录。桌面构建与验证说明见 [desktop/README.md](desktop/README.md)。

## 数据说明

数据位于当前浏览器的 localStorage（键 `next-small-step.v1`），不上传，也不跨设备同步。清理浏览器数据可能丢失记录，请定期导出备份。计时按时钟推进，浏览器关闭后仍会计算，到期在下次打开时记录；它不测量用户活动。暂停期间不计时。计时结束不自动完成任务。统计的“完成小步”和“达成目标”来自当前保留目标；删除目标后其专注历史仍保留。应用只保留一个活动计时。

2.1.0 起的完整备份封装包含目标、重要日期、全部专注记录、计时设置、主题、字号、遮罩、图标颜色、背景图片、更新及提醒偏好；2.3.0 起还包括每项待办的番茄预估与计数、每日番茄目标和白噪音设置。兼容旧版 v1/v2 进度备份，导入旧备份时保留当前外观。完整备份需用 2.1.0 及以上导入；通知权限仍由各设备系统管理。

外观入口位于导航区的“外观”。背景图片单独保存在本机 IndexedDB，颜色和遮罩偏好保存在独立的 localStorage 键；不占用任务存储，不上传图片。刷新或重开应用后恢复，随完整 JSON 备份迁移；恢复默认背景会移除已保存的图片。

`dist/core.js` 是可复用的数据校验、日期和计时逻辑；`dist/app.js` 管理交互与存储；`dist/planner.js` 管理日历和重要日期；样式文件定义响应式界面。所有用户内容都以纯文本渲染。

## 验证

逻辑测试需要 Node.js：

```sh
node --test tests/core.test.cjs tests/planner.test.cjs
```

浏览器流程测试需要 Windows、Microsoft Edge 和支持全局 `WebSocket` 的 Node.js（建议 Node.js 22 或更高版本）：

```sh
node tests/browser.cjs
node tests/pages.cjs
node tests/day-rollover.cjs
node tests/appearance.cjs
```

浏览器测试使用 Edge 的默认安装路径 `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`，并通过 CDP 检查真实交互；若 Edge 安装位置不同，需要调整 `tests/browser.cjs` 中的路径。测试使用 `.qa/` 下的隔离浏览器目录，不访问个人浏览器数据。
